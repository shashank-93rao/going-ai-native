# Postmortem: checkout degradation (INC-2857)

**Duration:** 2h 42m | **Author:** on-call, core team

## Summary

A configuration push set the checkout connection timeout to 50ms instead of 500ms. Customers saw elevated errors on checkout, search.

## Timeline (UTC)

- 11:50 Impact begins: error ratio on checkout starts rising.
- 12:25 First alert fired: error ratio above SLO on checkout.
- 12:28 Incident declared SEV3; incident commander assigned.
- 12:37 Upgraded to SEV2 after impact spread to search.
- 14:13 Mitigation applied.
- 14:32 Error rates back to baseline; incident resolved.

## Root cause

A configuration push set the checkout connection timeout to 50ms instead of 500ms. The change was applied fleet-wide without a canary because the config pipeline treated it as low risk.

## Impact

Customers saw elevated errors on checkout, search. Affected services: checkout, search.

## Action items

- [ ] Route timeout changes through the canary stage
- [ ] Add a lint rejecting timeouts under 100ms
