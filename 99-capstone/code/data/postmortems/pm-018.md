# Postmortem: ledger degradation (INC-2690)

**Severity:** SEV2 | **Duration:** 2h 26m | **Author:** on-call, payments team

## Summary

A release of ledger (v4.12.0) changed the retry policy on the outbound client from 3 attempts with backoff to unbounded immediate retries. Customers saw elevated errors on ledger, notifications.

## Timeline (UTC)

- 20:13 First alert fired: error ratio above SLO on ledger.
- 20:16 Incident declared SEV2; incident commander assigned.
- 22:14 Mitigation applied.
- 22:19 Error rates back to baseline; incident resolved.

Later log analysis showed impact actually began at 19:53, before any alert.

## Root cause

A release of ledger (v4.12.0) changed the retry policy on the outbound client from 3 attempts with backoff to unbounded immediate retries. Under normal error rates this amplified load on kafka-ingest.

## Impact

Customers saw elevated errors on ledger, notifications. Affected services: ledger, notifications.

## Action items

- [ ] Add a retry budget to the shared HTTP client
- [ ] Require canary analysis for client library changes
