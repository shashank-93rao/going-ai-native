# Postmortem: ledger degradation (INC-2599)

**Author:** on-call, platform team

## Summary

A schema migration on ledger backfilled NULL into a column the read path assumed was non-null. Customers saw elevated errors on ledger, notifications.

We initially suspected checkout because its dashboards were noisy, but its error rate and latency were within normal bounds throughout and it was not affected.

## Timeline (UTC)

- 12:10 Impact begins: error ratio on ledger starts rising.
- 12:24 First alert fired: error ratio above SLO on ledger.
- 12:27 Incident declared SEV3; incident commander assigned.
- 12:36 Upgraded to SEV2 after impact spread to notifications.
- 13:05 Mitigation applied.
- 13:11 Error rates back to baseline; incident resolved.

Customer-visible impact lasted from 12:10 until resolution at 13:11.

## Root cause

A schema migration on ledger backfilled NULL into a column the read path assumed was non-null. Rows written during the backfill window failed deserialization.

## Impact

Customers saw elevated errors on ledger, notifications. Affected services: ledger, notifications.

## Action items

- [ ] Make the backfill write a sentinel instead of NULL
- [ ] Add a contract test for nullable columns
