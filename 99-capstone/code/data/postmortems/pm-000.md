# Postmortem: auth degradation (INC-2700)

**Severity:** SEV3 | **Duration:** 2h 26m | **Author:** on-call, platform team

## Summary

A release of auth (v4.12.0) changed the retry policy on the outbound client from 3 attempts with backoff to unbounded immediate retries. Customers saw elevated errors on auth, ledger, payments.

We initially suspected kafka-ingest because its dashboards were noisy, but its error rate and latency were within normal bounds throughout and it was not affected.

## Timeline (UTC)

- 08:16 Impact begins: error ratio on auth starts rising.
- 08:24 First alert fired: error ratio above SLO on auth.
- 08:27 Incident declared SEV3; incident commander assigned.
- 10:15 Mitigation applied.
- 10:42 Error rates back to baseline; incident resolved.

## Root cause

A release of auth (v4.12.0) changed the retry policy on the outbound client from 3 attempts with backoff to unbounded immediate retries. Under normal error rates this amplified load on notifications.

## Impact

Customers saw elevated errors on auth, ledger, payments. Affected services: auth, ledger, payments.

## Action items

- [ ] Add a retry budget to the shared HTTP client
- [ ] Require canary analysis for client library changes
