# Postmortem: inventory degradation (INC-2683)

**Author:** on-call, core team

## Summary

A configuration push set the inventory connection timeout to 50ms instead of 500ms. Customers saw elevated errors on inventory, ledger.

## Timeline (UTC)

- 17:23 Impact begins: error ratio on inventory starts rising.
- 17:48 First alert fired: error ratio above SLO on inventory.
- 17:51 Incident declared SEV3; incident commander assigned.
- 18:00 Upgraded to SEV2 after impact spread to ledger.
- 20:19 Mitigation applied.
- 20:29 Error rates back to baseline; incident resolved.

Customer-visible impact lasted from 17:23 until resolution at 20:29.

## Root cause

A configuration push set the inventory connection timeout to 50ms instead of 500ms. The change was applied fleet-wide without a canary because the config pipeline treated it as low risk.

## Impact

Customers saw elevated errors on inventory, ledger. Affected services: inventory, ledger.

## Action items

- [ ] Route timeout changes through the canary stage
- [ ] Add a lint rejecting timeouts under 100ms
