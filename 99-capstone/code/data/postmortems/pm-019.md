# Postmortem: auth degradation (INC-2167)

**Severity:** SEV2 | **Duration:** 2h 4m | **Author:** on-call, payments team

## Summary

A configuration push set the auth connection timeout to 50ms instead of 500ms. No customer-facing impact; internal batch jobs and dashboards were delayed.

We initially suspected inventory because its dashboards were noisy, but its error rate and latency were within normal bounds throughout and it was not affected.

## Timeline (UTC)

- 12:56 Impact begins: error ratio on auth starts rising.
- 13:02 First alert fired: error ratio above SLO on auth.
- 13:05 Incident declared SEV2; incident commander assigned.
- 14:37 Mitigation applied.
- 15:00 Error rates back to baseline; incident resolved.

## Root cause

A configuration push set the auth connection timeout to 50ms instead of 500ms. The change was applied fleet-wide without a canary because the config pipeline treated it as low risk.

## Impact

No customer-facing impact; internal batch jobs and dashboards were delayed. Affected services: auth, ledger, notifications.

## Action items

- [ ] Route timeout changes through the canary stage
- [ ] Add a lint rejecting timeouts under 100ms
