# Postmortem: auth degradation (INC-2431)

**Severity:** SEV1 | **Duration:** 4h 15m | **Author:** on-call, core team

## Summary

A release of auth (v4.12.0) changed the retry policy on the outbound client from 3 attempts with backoff to unbounded immediate retries. Customers saw elevated errors on auth, checkout.

We initially suspected notifications because its dashboards were noisy, but its error rate and latency were within normal bounds throughout and it was not affected.

## Timeline (UTC)

- 12:32 Impact begins: error ratio on auth starts rising.
- 12:53 First alert fired: error ratio above SLO on auth.
- 12:56 Incident declared SEV1; incident commander assigned.
- 16:34 Mitigation applied.
- 16:47 Error rates back to baseline; incident resolved.

## Root cause

A release of auth (v4.12.0) changed the retry policy on the outbound client from 3 attempts with backoff to unbounded immediate retries. Under normal error rates this amplified load on checkout.

## Impact

Customers saw elevated errors on auth, checkout. Affected services: auth, checkout.

## Action items

- [ ] Add a retry budget to the shared HTTP client
- [ ] Require canary analysis for client library changes
