# Postmortem: auth degradation (INC-2756)

**Severity:** SEV2 | **Author:** on-call, payments team

## Summary

Our upstream card-network provider returned intermittent 503s. Customers saw elevated errors on auth, inventory.

We initially suspected payments because its dashboards were noisy, but its error rate and latency were within normal bounds throughout and it was not affected.

## Timeline (UTC)

- 14:37 First alert fired: error ratio above SLO on auth.
- 14:40 Incident declared SEV2; incident commander assigned.
- 16:57 Mitigation applied.
- 17:02 Error rates back to baseline; incident resolved.

Later log analysis showed impact actually began at 13:59, before any alert.

Customer-visible impact lasted from 13:59 until resolution at 17:02.

## Root cause

Our upstream card-network provider returned intermittent 503s. auth had no circuit breaker on that call path, so request threads blocked on the provider until pools were exhausted.

## Impact

Customers saw elevated errors on auth, inventory. Affected services: auth, inventory.

## Action items

- [ ] Add a circuit breaker on the provider call path
- [ ] Bulkhead provider calls into their own pool
