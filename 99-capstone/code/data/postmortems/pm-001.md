# Postmortem: kafka-ingest degradation (INC-2371)

**Duration:** 49m | **Author:** on-call, payments team

## Summary

A configuration push set the kafka-ingest connection timeout to 50ms instead of 500ms. Customers saw elevated errors on kafka-ingest.

## Timeline (UTC)

- 11:13 First alert fired: error ratio above SLO on kafka-ingest.
- 11:16 Incident declared SEV3; incident commander assigned.
- 11:25 Upgraded to SEV2 after impact spread to kafka-ingest.
- 11:18 Mitigation applied.
- 11:24 Error rates back to baseline; incident resolved.

Later log analysis showed impact actually began at 10:35, before any alert.

## Root cause

A configuration push set the kafka-ingest connection timeout to 50ms instead of 500ms. The change was applied fleet-wide without a canary because the config pipeline treated it as low risk.

## Impact

Customers saw elevated errors on kafka-ingest.

## Action items

- [ ] Route timeout changes through the canary stage
- [ ] Add a lint rejecting timeouts under 100ms
