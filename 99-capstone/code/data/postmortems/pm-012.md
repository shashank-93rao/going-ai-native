# Postmortem: notifications degradation (INC-2326)

**Severity:** SEV1 | **Duration:** 1h 57m | **Author:** on-call, platform team

## Summary

A release of notifications (v4.12.0) changed the retry policy on the outbound client from 3 attempts with backoff to unbounded immediate retries. No customer-facing impact; internal batch jobs and dashboards were delayed.

## Timeline (UTC)

- 17:36 Impact begins: error ratio on notifications starts rising.
- 18:13 First alert fired: error ratio above SLO on notifications.
- 18:16 Incident declared SEV1; incident commander assigned.
- 19:15 Mitigation applied.
- 19:33 Error rates back to baseline; incident resolved.

## Root cause

A release of notifications (v4.12.0) changed the retry policy on the outbound client from 3 attempts with backoff to unbounded immediate retries. Under normal error rates this amplified load on inventory.

## Impact

No customer-facing impact; internal batch jobs and dashboards were delayed.

## Action items

- [ ] Add a retry budget to the shared HTTP client
- [ ] Require canary analysis for client library changes
