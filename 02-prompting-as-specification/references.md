# References

Read on 2026-10-19 unless noted. Vendor docs are living pages, so re-check them before relying on a parameter name.

## Anthropic

- **[Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)**. The core reference for this module. Take from it: the golden rule (show the prompt to a colleague with minimal context), the ellipses/TTS example for explaining why, 3 to 5 examples in `<example>` tags, XML tags to separate instructions, context and inputs, long documents at the top, and the "dial back aggressive language" note. The section *Migrating away from prefilled responses* is the authority for "prefill returns a 400 on Claude 4.6+" and lists the replacement for each prefill use case. It also says techniques measured on one model should be re-checked against your own evals before you apply them to another.
- **[Prompting Claude Opus 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5)**. Take: explicit verification instructions cause over-verification; "only report high-severity issues" is followed literally, so report everything and filter separately; the verbatim scope prompt and subagent-damping prompt; effort as the primary cost lever, with a re-run of the effort sweep when you change models; and the `reasoning_extraction` refusal for prompts that ask for verbatim reasoning.
- **[Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)**. Take: `output_config.format` with `type: "json_schema"`, strict tool use, the supported JSON Schema subset (no `minLength`/`maximum`, `additionalProperties: false` required), the behaviour on `refusal` and `max_tokens`, grammar compilation latency and the 24-hour cache, and the complexity limits.
- **[An update on recent Claude Code quality reports (April 23 postmortem)](https://www.anthropic.com/engineering/april-23-postmortem)**. Take: the ≤25/≤100-word system-prompt line that cost 3% on Opus 4.6 and 4.7, and the process response (per-model evals for every system-prompt change, line-by-line ablations, model-gated changes, soak periods, gradual rollout). This is the case study for [06-prompts-as-deploys.md](06-prompts-as-deploys.md).
- **[The "think" tool](https://www.anthropic.com/engineering/claude-think-tool)** (2025-03-20, updated 2025-12-15). Take: the τ-bench airline table (Claude 3.7 Sonnet; think plus prompt pass^1 0.584 against a 0.332 baseline), and the update recommending extended thinking instead "in most cases". The page's prose cites slightly different numbers than its table, so cite the table. It's the course's standard example of a technique that expired.
- **[Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)** (2025-09-29). Take: the "right altitude" for system prompts, starting minimal and adding instructions for observed failures, and canonical diverse examples over lists of edge cases. More in [Module 03](../03-context-engineering/README.md).
- **[Claude Code: How Claude remembers your project](https://code.claude.com/docs/en/memory)**. Take: CLAUDE.md is "delivered as a user message after the system prompt"; it is "context, not enforced configuration"; conflicting instructions may be resolved arbitrarily; user and project rules don't override each other; use a PreToolUse hook to block an action; AGENTS.md loading rules; and `/doctor prompt-audit` (v2.1.283+).
- **[Automating eval design and hillclimbing with Claude](https://claude.dev/blog/automating-eval-design-and-hillclimbing/)** (2026-09/10). Referenced for the "revert when train rises and test stays flat" rule. Details in [Module 12](../12-hill-climbing/README.md).

## OpenAI

- **[Prompt guidance, GPT-5.5](https://developers.openai.com/api/docs/guides/prompt-guidance?model=gpt-5.5)**. Take: "describe the destination rather than every step"; legacy prompts "over-specify the process" and can "narrow the model's search space"; start migrations "with a fresh baseline"; start with "the smallest prompt that preserves the product contract"; use ALWAYS/NEVER only "for true invariants"; avoid describing the output schema in the prompt when you use Structured Outputs; `medium` effort as the starting point.
- **[Prompt guidance, GPT-6 family](https://developers.openai.com/api/docs/guides/prompt-guidance)**. Take: GPT-6 "can be more sensitive to instructions contained in skills and other files, such as `AGENTS.md`"; "The user's instructions take precedence over guidelines provided in a skill"; ask for approval "only after preparing a concrete, reviewable result"; don't write tests for reversible, low-impact changes that "mirror the implementation".
- **[OpenAI Model Spec (2026-08-18)](https://model-spec.openai.com/2026-08-18.html)**. Take: the chain of command (Root, System, Developer, User, Guideline) and the "No Authority" status of tool outputs, quoted text and file attachments.
- **[GPT-4.1 prompting guide](https://developers.openai.com/cookbook/examples/gpt4-1_prompting_guide)** (April 2025, archived). Take: the three agentic reminders and their "close to 20%" SWE-bench Verified gain, +4% from planning, and the note on literal instruction following. The course uses it as evidence that process prompting *was* right for its model.
- **[GPT-5 prompting guide](https://developers.openai.com/cookbook/examples/gpt-5/gpt-5_prompting_guide)** (archived). Take: contradictory instructions make the model spend reasoning tokens reconciling them, and audit your prompt library for conflicts.
- **[Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices)**. Take: "Avoid chain-of-thought prompts"; "think step by step" "may not enhance performance (and can sometimes hinder it)".
- **[Introducing Structured Outputs in the API](https://openai.com/index/introducing-structured-outputs-in-the-api/)** (2024-08-06). Take: constrained decoding via a compiled grammar, and the 100% vs under-40% schema-adherence comparison. *Not re-verified for this module (HTTP 403 on fetch). The figures, including the 93% prompting-only number in the research notes, are as reported.*
- **[Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)**. Take: the order in which Codex assembles permissions, developer instructions, AGENTS.md and the user message. Used in [04-instruction-hierarchy.md](04-instruction-hierarchy.md) as a contrast to Claude Code. Taken from the research notes, not re-fetched.
- **[Harness engineering](https://openai.com/index/harness-engineering/)**. Take: lints whose error messages carry remediation text. Taken from the research notes, not re-fetched.

## Practitioners

- **[repomirror write-up](https://github.com/repomirrorhq/repomirror/blob/main/repomirror.md)** (around 2025-08). Take: a 1,500-word "improved" prompt made the agent worse, and they cut it back to 103 words. Evidence against fixing ambiguity by piling on rules.
- **[Simon Willison on the GPT-5.5 prompting guide](https://simonwillison.net/2026/Apr/25/gpt-5-5-prompting-guide/)**. A readable summary of the "fresh baseline" advice, with the link to OpenAI's page.
